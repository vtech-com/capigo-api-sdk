## 1. Context

Phase 0.1 shipped auth, config, tenants, tasks, and boards. The `products` command group was explicitly deferred pending 5 defects in `api/openapi.json` and the product write APIs being unmerged on the Capigo backend.

Those APIs have since merged into `capigo` develop as v1.20.0 (feature/epic-11-story-11.8-pcms-product-write-api). The 5 known defects plus 1 additional defect (variants upsert body schema) are now fixable because the authoritative spec is available.

## 2. Counter-review findings (pre-implementation audit)

The following issues were identified before writing any code. All are addressed in this plan.

### 2.1 OpenAPI defects (6 total — original list said 5)

| # | Defect | Fix |
|---|--------|-----|
| 1 | **Path double-prefix**: POST/PUT paths use `/api/v1/pcms/...` but servers already prefix `/api/v1` | Change path keys to `/pcms/products`, `/pcms/products/{id}`, `/pcms/products/{id}/variants` |
| 2 | **Broken `$ref` — response**: 3 write endpoints ref `#/components/schemas/Product` (does not exist) | Change to `#/components/schemas/PublicProductResponse` |
| 3 | **Broken `$ref` — error**: 3 write endpoints ref `#/components/schemas/ErrorResponse` (does not exist) | Change to `#/components/schemas/Error` |
| 4 | **Tenant header missing**: write paths have no `X-Tenant-Code` parameter documented | Add `X-Tenant-Code` header parameter (required: true) to all 3 write paths |
| 5 | **Status enum casing**: `PublicProductResponse.status` uses lowercase (`active`, `draft`, `archived`); backend and write requests use UPPERCASE | Update response schema enum to `DRAFT`, `ACTIVE`, `ARCHIVED` |
| 6 | **Variants upsert body schema** (new): `variant_id` is marked `required` — locks to UPDATE-only semantics. Actual API supports mixed create+update: `variant_id` present → UPDATE, absent → CREATE (must have `name`) | Remove `variant_id` from `required` array; add `name` field with note |

Also: create-request variants array is missing `option1`, `option2`, `option3` fields. These are documented in the spec brief and accepted by the API — add them.

### 2.2 HTTP client gap

`client.Do()` currently captures `X-Request-Id` from the response header but silently discards all other headers including `X-Server-Time`. For delta sync (`GET /pcms/products`) to work correctly, callers need the server timestamp.

Fix: add `ServerTime string` to the `Response` struct and populate it from `X-Server-Time` header in `client.Do()`.

### 2.3 Missing output types

`internal/output/types.go` has no `Product` display type. `internal/output/formatter.go` has no `"product"` renderer entry. Both are required before `cmd/products.go` can call `output.Render`.

### 2.4 Flag design for write commands

The `options`/`variants` arrays in `products create` are too complex to express as individual flags cleanly. Pattern adopted:

- Simple product: use individual flags (`--name`, `--sku`, `--price`, etc.)
- Product with options + variants: use `--from-json <file>` or `--from-json -` (stdin) accepting the full request body as JSON

This mirrors the pattern used by `gh`, `stripe`, and `kubectl` for complex payloads. The simple-flag path covers 80% of "Tấm agent" use cases (single-variant product import); the `--from-json` path covers the rest.

For `products variants` (upsert), the payload is always a JSON array — `--from-json` is the only flag needed (no way to express a mixed create/update array with individual flags).

### 2.5 CLI tenant enforcement

`products list`, `products create`, `products update`, and `products variants` all target `/pcms/*`. Per §5.3 rule #2, the CLI must reject early if no tenant is resolved. The constant `api.PCMSRequiresTenant` already encodes this; `cmd/products.go` must check it using the same pattern as `tasksCreateCmd`.

## 4. API contract (authoritative — from capigo develop v1.20.0)

### Auth
- `Authorization: Bearer {api_key}` — always required
- `X-Tenant-Code: {tenant_code}` — required for all `/pcms/*` endpoints (CLI rejects early if absent)

### GET /pcms/products
Query: `page` (int, default 1), `limit` (1–100, default 20), `updated_since` (ISO 8601 UTC)
Response header: `X-Server-Time` — use as `updated_since` for next delta sync
Response 200: `{ data: Product[], meta: { page, limit, total, has_more } }`

### POST /pcms/products
Request body: `name` (required, max 500), `description`, `brand_id`, `category_id`, `product_type_id`, `unit_id`, `status` (DRAFT|ACTIVE|ARCHIVED, default DRAFT), `currency` (default VND), `sku`, `barcode`, `price`, `options[{name, values[]}]`, `variants[{name, sku, barcode, price, option1, option2, option3}]`
- `name` alone → simple product with 1 default variant
- `options` present → `variants` required; backend does NOT auto-generate Cartesian matrix
Response 201: `{ data: Product }`

### PUT /pcms/products/{id}
Request body: all fields optional, at least 1 required. Fields: `name`, `description`, `brand_id`, `category_id`, `product_type_id`, `unit_id`, `status`, `aliases[]`, `currency`
Response 200: `{ data: Product }`

### PUT /pcms/products/{id}/variants
Request body: array (max 50 items). Each item: `variant_id` (present → UPDATE, absent → CREATE — `name` required for CREATE), `name`, `sku`, `barcode`, `price`, `option1`, `option2`, `option3`
Response 200: `{ data: Product }`

## 6. Implementation details

### 6.1 `internal/api/client.go` change

```go
type Response struct {
    StatusCode int
    Body       []byte
    RequestID  string
    ServerTime string // X-Server-Time response header; empty if absent
}
```

Populate: `r.ServerTime = resp.Header.Get("X-Server-Time")` after reading the body.

### 6.2 `internal/api/models.go` additions

```go
// CreateProductOptionItem is one option axis for POST /pcms/products.
type CreateProductOptionItem struct {
    Name   string   `json:"name"`
    Values []string `json:"values"`
}

// CreateProductVariantItem is one variant for POST /pcms/products.
type CreateProductVariantItem struct {
    Name    string   `json:"name"`
    SKU     *string  `json:"sku,omitempty"`
    Barcode *string  `json:"barcode,omitempty"`
    Price   *float64 `json:"price,omitempty"`
    Option1 *string  `json:"option1,omitempty"`
    Option2 *string  `json:"option2,omitempty"`
    Option3 *string  `json:"option3,omitempty"`
}

// CreateProductRequest is the body for POST /pcms/products.
type CreateProductRequest struct {
    Name          string                     `json:"name"`
    Description   *string                    `json:"description,omitempty"`
    BrandID       *string                    `json:"brand_id,omitempty"`
    CategoryID    *string                    `json:"category_id,omitempty"`
    ProductTypeID *string                    `json:"product_type_id,omitempty"`
    UnitID        *string                    `json:"unit_id,omitempty"`
    Status        *string                    `json:"status,omitempty"`
    Currency      *string                    `json:"currency,omitempty"`
    SKU           *string                    `json:"sku,omitempty"`
    Barcode       *string                    `json:"barcode,omitempty"`
    Price         *float64                   `json:"price,omitempty"`
    Options       []CreateProductOptionItem  `json:"options,omitempty"`
    Variants      []CreateProductVariantItem `json:"variants,omitempty"`
}

// UpdateProductRequest is the body for PUT /pcms/products/{id}.
// All fields are optional pointers; only non-nil fields are serialized.
type UpdateProductRequest struct {
    Name          *string  `json:"name,omitempty"`
    Description   *string  `json:"description,omitempty"`
    BrandID       *string  `json:"brand_id,omitempty"`
    CategoryID    *string  `json:"category_id,omitempty"`
    ProductTypeID *string  `json:"product_type_id,omitempty"`
    UnitID        *string  `json:"unit_id,omitempty"`
    Status        *string  `json:"status,omitempty"`
    Currency      *string  `json:"currency,omitempty"`
    Aliases       []string `json:"aliases,omitempty"`
}

// UpsertVariantItem is one element of the PUT /pcms/products/{id}/variants array.
// VariantID present → UPDATE; absent → CREATE (Name required).
type UpsertVariantItem struct {
    VariantID *string  `json:"variant_id,omitempty"`
    Name      *string  `json:"name,omitempty"`
    SKU       *string  `json:"sku,omitempty"`
    Barcode   *string  `json:"barcode,omitempty"`
    Price     *float64 `json:"price,omitempty"`
    Option1   *string  `json:"option1,omitempty"`
    Option2   *string  `json:"option2,omitempty"`
    Option3   *string  `json:"option3,omitempty"`
}
```

### 6.4 `cmd/products.go` command surface

```
capigo products list       [--tenant <code>] [--updated-since <ISO8601>] [--page N] [--limit N] [--all]
capigo products create     --name <str> [--description <str>] [--status DRAFT|ACTIVE|ARCHIVED]
                           [--currency <str>] [--sku <str>] [--barcode <str>] [--price <float>]
                           [--brand-id <uuid>] [--category-id <uuid>]
                           [--product-type-id <uuid>] [--unit-id <uuid>]
                           [--from-json <file|-]  (when provided, --name and item flags are ignored)
capigo products update     --id <uuid> [--name <str>] [--description <str>] [--status <str>]
                           [--currency <str>] [--brand-id <uuid>] [--category-id <uuid>]
                           [--product-type-id <uuid>] [--unit-id <uuid>]
capigo products variants   --product-id <uuid> --from-json <file|->
```

All commands:
- Reject early if no tenant resolved (`api.PCMSRequiresTenant`)
- Pass tenant via `X-Tenant-Code` header (not body field — product endpoints use header, not body)
